开源项目

BioinfoFlow

Agent 驱动的生信工作流平台。独立开发，MIT 开源。2025.12 至今，为业余个人项目，与华大在职时间并行。

bioinfoflow.com · GitHub · Python、TypeScript、FastAPI、Next.js、Docker

用户用自然语言描述分析任务。Agent 读取项目文件，准备输入和参数。用户批准后，Agent 提交 Nextflow 或 WDL 任务，然后跟踪日志并解释结果。数据和运行环境都留在用户自己的机器或服务器上。

  • 自研 Agent 运行时。会话持久化，历史只追加。模型只用 read、bash、edit、write、ask_user 等少量通用工具，经 CLI 调用平台能力。
  • 运行时支持上下文压缩、重试、取消和断点恢复。权限分三级：改动需确认、危险操作需确认、完全访问。
  • 后端用 FastAPI 和 Typer CLI。执行层抽象出 Nextflow 与 MiniWDL 两套引擎。
  • 常驻调度器负责排队、资源检查、重试、超时和清理。运行状态经 SSE 和 WebSocket 推送到前端。
  • 前端用 Next.js。页面包括工作区、仪表盘、Agent、工作流、运行记录（日志、DAG、产物）、镜像管理、调度器和设置。
  • 支持 SSH 远程主机：保存连接配置、测试主机、在浏览器内开终端，并可把选定主机交给 Agent 操作。远程 Agent 命令在 Bubblewrap 沙盒中执行。
  • 用 Docker Compose 打包，一行命令安装。GitHub 上已发布 v0.1.0（2026.07）和 v0.2.0（2026.07）。
  • 仓库附带 nf-core/rnaseq 示例、WDL 测试用例和 NVIDIA Parabricks WGS 示例，可在单张消费级 GPU（如 RTX 4080 SUPER）上运行 GPU 流程。

Trove

GitHub Star 仓库工作台。MIT 开源。2026.11。

GitHub · TypeScript、Next.js、React、SQLite

Trove 在自己的机器上整理你在 GitHub 上 Star 过的仓库。数据存在本地 SQLite。

  • 用标签和收藏夹整理仓库。配置模型后，AI 可以自动分类。
  • 仓库关系图按共享的标签、收藏夹和 topic 连接仓库，用力导向布局绘制。
  • Radar 从 GitHub 搜索和 Hacker News 等来源推荐新仓库。
  • Releases 收件箱汇总正在使用的仓库的新版本，并标出可能的破坏性更新。
  • AI 为仓库生成健康报告。
  • 内置 MCP 服务，编程助手可用 token 调用。命令行工具负责签发和吊销 token。
  • 模型支持 OpenRouter、OpenAI、Anthropic、DeepSeek、本地 Ollama 和 OpenAI 兼容服务。Ollama 地址只接受本机回环地址。
  • 界面支持中英文。可以用 Docker Compose 部署。

Loadout

macOS 上的 AI Agent 技能管理工具。独立开发，MIT 开源。2026.10。

GitHub · Rust、Tauri 2、React、SQLite

  • 已发布 v0.2.1 Universal 版本，可在 Apple Silicon 和 Intel Mac 上原生运行。
  • 扫描 ~/.agents 和 Claude Code、Codex、Cursor、Gemini、OpenCode 的技能目录，合并成一份去重列表。软链接只算一份技能、多处安装。
  • 在应用内安装、更新和删除技能。更新前保留旧目录作为备份，删除的文件进废纸篓。
  • 用 Rust 实现目录扫描、防抖文件监听和会话日志解析。使用记录增量写入 SQLite，只存技能名、Agent 和日期，不复制提示词和回复。
  • 根据使用记录生成热力图。界面支持中英文，以及浅色、深色和跟随系统三种外观。
  • 不申请完全磁盘访问、自动化、辅助功能或录屏权限。

Folio

本地 Markdown 阅读库，用来读 X 上收藏的长文。Apache-2.0 开源，macOS Apple Silicon 预览版。2026.11。

GitHub · TypeScript、Electron、React

  • 通过 Chrome 扩展，从 X 收藏里导入长文。导入在后台请求，不打开或刷新 X 标签页。
  • 文章存成本地 Markdown，图片也存到本地。同一文件夹可以直接用 Obsidian 或 Cursor 打开。
  • 按主题和阅读状态浏览文章，可以打分和加批注。
  • 可选接入自有模型 API，把选中的文章整理成主题笔记和卡片。保存前由用户审核。API key 用系统安全存储加密。
  • 界面支持中英文，以及浅色、深色和跟随系统三种外观。

我一人完成这套服务的设计、部署、监控和文档。

  • 在部门 8 卡 H20 服务器上用 vLLM 部署 DeepSeek-V4-Flash。配置为 8 卡张量并行、专家并行和 FP8 KV cache。服务以 OpenAI 兼容 API 提供给 OpenWebUI、BioinfoFlow 和同事的项目。

  • 搭建 LiteLLM 网关。每个同事、项目和服务各用一个 virtual key，原始模型 key 不外发。每个 key 可限制每分钟请求数、每分钟 token 数、预算和并行请求数。
  • 写了 key 管理脚本，覆盖创建、查看、禁用、恢复和轮换。
  • 用 Prometheus 采集指标，用 DCGM exporter 采集 GPU 指标，用 Grafana 做面板。
  • 自建两个 Grafana 面板。容量面板显示健康状态、估算剩余并发、运行和排队请求数、KV cache 使用率、TTFT P95 和 TPOT P95。用量面板按 key 统计请求数和 token 数。
  • 发现服务器时钟比真实时间快约 8 小时后，在面板查询中加时间补偿，并写明修复 NTP 后要删除补偿。
